# fixtures · 自带的合成测试语料

这一套语料用于**端到端验证解析引擎**，随仓库分发，任何人 clone 下来都能直接跑
`node _smoke/fixture.test.js`，不需要自备数据。

## 为什么需要它

真实教辅（行测等）有版权，不能进仓库。如果端到端验证只依赖仓库外的语料，
别人 clone 下来就跑不了、CI 也只能跳过 —— 等于没有验证。

## 为什么这套语料没有版权问题

| 内容 | 来源 | 依据 |
|---|---|---|
| 数学计算题 | 程序生成，答案由计算得出 | 非复制，脚本原创 |
| 古诗填空 | 唐宋名家千古名句 | 作者逝世远超 50 年，属**公有领域** |
| 常识判断题 | 客观事实（水的沸点、行星数量、元素序号……） | **事实本身不受著作权保护**，题干表述由脚本自行组织 |
| 干扰项 | 脚本按数值邻近 / 同类混淆自动生成 | 非摘抄 |

## 文件

| 文件 | 用途 |
|---|---|
| `合成题本.txt` | 6 章分卷题本，题号在每章重置（测顺序对齐） |
| `合成解析.txt` | 配套解析，每章换一种答案写法 |
| `合成题本-单卷.txt` | 单卷 20 题，题号全局唯一（测按题号对齐） |
| `合成解析-聚合.txt` | 聚合式 `1-5. A B C D A` + 单行多题 `11.D 12.A` |
| `合成题本-文末答案.txt` | 单卷题本 + 末尾「参考答案」区（测文末答案切分） |
| `expected.json` | 每题的期望题号 / 题型 / 答案，供逐题断言 |

## 怎么配对（三套语料别配错）

文件名长得像，配错了不会报错，只会**悄悄判错**，所以对着这张表配：

| 题本 | 该配的答案文件 | 对齐方式 |
|---|---|---|
| `合成题本.txt` | `合成解析.txt` | 顺序对齐（题号每章重置） |
| `合成题本-单卷.txt` | `合成解析-聚合.txt` | 按题号对齐（题号全局唯一） |
| `合成题本-文末答案.txt` | 不用配，它自带文末答案区 | 顺序对齐 + 文末答案源 |

配错会怎样：例如把单卷题本配上 `合成解析.txt`，顺序对齐仍会硬配 20 条，
其中 4 条是判断题答案「对 / 错」—— 挂着四选一的题目。引擎现在会**主动放弃**这类答案
（题目卡上说明「标准答案写的是『正确』，但这道题有 4 个选项」），而不是把它当成
一道「带 4 个选项的判断题」照常判分（那样考生选 C 永远判错）。这组错配在
`fixture.test.js` 里有专门用例守着。

## 语料刻意覆盖的形态

除了正常题目，里面还插了这些真实 OCR 语料里会把切题搞乱的东西，
用来守住引擎的对应防护：

- 表格数值行（`460.6 4077.5 2162.3`）—— 不能变成题
- 水印推广行（`免费公众号…`）—— 不能进题干
- 方法讲解块（`考点介绍` + 内部 `1. 2. 3.`）—— 不能变成伪题
- 资料分析材料块（`（2023上海B…）根据下列资料…` + 数字串）—— 不能变成题
- 题干续行（行首是 `1.5倍…` 但上一行没结束）—— 必须并入上一题
- 题号 + 年份开头（`4.2021年，表中所列…`）—— 必须识别为题目，不能误判成小数
- CRLF 换行（与真实 OCR 语料一致）

## 重新生成

```bash
node tools/gen-fixture.js
```

生成器用固定种子，同一份种子产出同一份语料，可以重复验证。
改了题目素材或章节配置后重新生成，`expected.json` 会同步更新。
